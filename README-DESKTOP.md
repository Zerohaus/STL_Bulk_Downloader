# Bulk Downloader (Desktop v2.0.0)

Desktop app (Electron) + Bash/PowerShell scripts to bulk-download **your** MyMiniFactory library.

## Quick start (recommended)

1. `npm install` then `npm start`
2. **Open MyMiniFactory** → sign in → **Capture session**
3. **Auto load my IDs** (catalog loads in pages of 25 from the store API)
4. Remove any models you do not want from the list
5. **Execute Pipeline** (Step 1 metadata → Step 2 test → Step 2 full)

See also: [DESKTOP_EXE.md](DESKTOP_EXE.md) (build installer), [CHANGELOG.md](CHANGELOG.md).

## Rate limits (conservative)

| Step | Delay |
|------|--------|
| Metadata (Step 1) | 6 s between models |
| STL/ZIP (Step 2) | 5 s between files |
| Images | 3 s |
| Catalog pages | 1 s between store API pages |

## Resume after session expiry

- Step 1 skips existing `model_<id>.json` files.
- Step 2 skips files already on disk.
- **Windows packaging:** the installer ships `tools/zip.exe` (Info-ZIP 3.0) so clients do not need to install `zip` separately. Each `.rar`/`.7z` from MMF is wrapped in its own `.zip` (`file.rar` → `file.zip`). MMF-delivered `.zip` files are left as-is.
- If the session expires mid-run, capture a new session and re-run; completed work is kept.

## Auth

- Primary: embedded browser + **Capture session** (encrypted storage when OS keychain is available).
- Fallback: **Advanced → manual credentials** in the Configuration panel.

## Windows dependencies (Steps 1–2)

Steps 1 and 2 are **Bash scripts** (`.sh`). On Windows the desktop app runs them with **Git Bash** from [Git for Windows](https://git-scm.com/download/win). The startup dependency gate checks for Bash, `curl`, and `jq`.

Git for Windows also ships **Perl** (`usr/bin/perl`). Step 2 uses it internally to normalize lookalike Unicode letters in MyMiniFactory filenames (e.g. Greek `Ι` → Latin `I` in Roman numerals). You do **not** need to install Perl separately.

Steps 3–4 on Windows use **PowerShell** (`.ps1`); macOS/Linux use the `.sh` variants.

## Troubleshooting Step 2 write errors

If the log shows **“Could not write download to disk”** but free space looks fine (hundreds of GB), the drive is usually not full. Common causes:

- Real-time antivirus or cloud sync (OneDrive, etc.) locking files during download
- Output path too long — try a short folder such as `D:\MMF`
- Read-only or permission-restricted destination

Exclude the downloads folder from live scanning if possible, then re-run Step 2 (already-complete files are skipped).

## Output layout

Each completed model becomes one folder:

```
stl_files/<id>_<Slug>/
├── <Slug>.zip            flat archive of every file the API lists
├── images/
│   ├── thumbnail_image.jpg
│   └── <other images>
└── model_<id>.json
```

Nested `.zip` members are expanded into the flat archive rather than nested, and
member names are sanitised the same way folder names are. Plain files are stored
uncompressed; anything unpacked out of a `.zip` is deflated.

Models are assembled under `.mmf_staging/` and moved into place only once the
archive exists, so nothing scanning the library sees a half-built folder. If a run
is interrupted, leftover work stays in `.mmf_staging/` and the next run picks it up.

## Pacing and rate limits

Step 2 fetches each model with a single `/download/<id>` request where MyMiniFactory
has a generated archive, falling back to per-file downloads otherwise. The gap
between requests adapts on its own — it widens after a throttle and narrows again
after a clean run — because the limiter is not a fixed published quota.

| Variable | Default | Purpose |
|---|---|---|
| `MMF_WHOLE_MODEL_ROUTE` | `1` | Set `0` to always download file-by-file |
| `MMF_STL_FILE_DELAY_SEC` | `5` | Floor for the gap between download requests |
| `MMF_ADAPTIVE_PACING` | `1` | Set `0` for a fixed gap instead |
| `MMF_ADAPTIVE_DELAY_MAX_SEC` | `120` | Ceiling the gap can widen to |
| `MMF_ADAPTIVE_RECOVERY_STREAK` | `10` | Clean downloads needed before it narrows |
| `MMF_STAGING_ROOT` | `.mmf_staging` | Where models are assembled |

A `403` is normally a timed throttle, not an expired cookie — the script waits it
out. See `_tools/MMF_DOWNLOADER_FINDINGS.md` for the measurements behind all of this.
